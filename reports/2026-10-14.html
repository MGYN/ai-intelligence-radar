  1. Anthropic 公开 Scion：日合并量 5 个月涨 12 倍，git 撑不住，自研「为 Agent 规模设计」的版本控制系统，5 个月内迁离 git

ANEW国际B/C/Dengineering 博文页标 Oct 13@AnthropicAI 10-14 00:36 CST

发生了什么（事实，均为 Anthropic 单方数据）

  • 规模：Anthropic 单仓每日合并量从 2026-05 约 2,500 增至 9 月的 30,000+；main 历史接近 100GB，压缩后工作副本 25GB+；CI 每天约 2,500 万次 checkout（如果按普通方式拉取，git 流量将超过 600PB / 日）；高峰期需要运维数百个 git mirror。
  • Scion 的设计原则：客户端永远在线；客户端与服务端不对称（history / blame / commit / merge / rebase 都在服务端完成，客户端只保留有界缓存）；全部水平扩展，不用 packfile；提交廉价、增量、无锁；工作副本可选，默认稀疏。所有查询 API 化，CI、bisect、revert 不需要建本地仓。
  • 配套：自建代码评审界面 Antique、代码搜索、源码 IAM；放弃全局合并锁，改为依赖合并后 / 部署前的自动测试，冲突由 Claude 修复。
  • 不开源：官方称 Scion 不适合作为通用的 git 替代品，转而呼吁与 GitHub / GitLab / 开源社区一起推动服务端 RPC 标准化；预计 6–12 个月内会有更多团队遇到同类瓶颈。

我的判断

  • 这是一线厂第一次公开「agent 产码量压垮 git 基础设施」的量化证据和架构答案。和 Daily 10-13 的 Perplexity Projects Git forge 放在一起看：Agent 时代的代码托管层正在重构。Perplexity 选择保留 git 语义，Anthropic 直接把 git 换掉。
  • 放弃合并锁、依赖事后验证，是用吞吐换一致性，质量风险能否被自动测试和 Claude 修复兜住，文中没有给出数据。

往后看：GitHub / GitLab 对「服务端 RPC 标准」的回应；同类托管层动向，例如 Cursor 同日开放 Origin 代码托管的 App Marketplace（20+ CI / 部署 / 评审 / 安全应用，app JWT + installation token）。

利益相关提示：Cursor 与 Grok Bot 同属 X Subscription 产品线，此处只记事实，不单独入栏。

对智能体互联网：中相关。源码 IAM（按 agent 细粒度读写）与「无锁提交 + 事后验证」，是多 agent 协作时信任边界设计的参考。

对 Work / Agent 引擎：强相关。Agent Workspace / Sandbox 不应假设「完整 clone」；服务端查询 + 稀疏懒加载工作副本 + 有界缓存，是 Cloud Agent 冷启动和多租户成本的关键。合并队列与 CI 语义需要按「千级并发变更」重新设计。

建议动作：① 统计自家 Cloud Agent 沙箱的 clone / checkout 时长与流量占比，评估稀疏 / 懒加载工作副本 PoC；② 跟进服务端 RPC 标准化讨论，自家 Workspace 的 git 访问层先做抽象，避免与 git 协议细节强耦合。

  • 实测：15 台约 $55 的杂牌 Android TV 盒联网，分布式推理 Gemma4-26B-A4B，速度 0.39 tok/s。复制链被拆成四个阶段：找目标、获得执行权、建立推理、继续传播；本文聚焦「在受害设备上建立推理」。
  • 威胁模型包括窃取 API 凭证驱动远端推理的复制体；没有中心化的关停点，倍增时间约为数天。

我的判断

  • 研究把「自主复制与适应（ARA）」风险从数据中心 GPU 推到了 IoT 僵尸网络场景：门槛是廉价设备 + 开放权重小模型，而不是前沿模型。
  • 中立性提示：文中以 GLM-5.2 为能力参照，结合 Anthropic 近期在反蒸馏、网络能力报告中多次点名智谱，这类表述带有立场色彩，应视为 Anthropic 一方的评测结论。截至本期未检索到智谱回应。

往后看：是否引出开放权重政策讨论；官方 X 是否补发；其他实验室能否复现。

对智能体互联网：中相关。如果 Agent 身份 / 凭证可以被窃取去驱动远端推理，就需要短期凭证 + 设备证明 + 异常调用速率检测。

  1. 自治 agent 实战入侵取证三连：SOCRadar「CyberXero」、breachcache「Hands Off the Keyboard」、Gurucul「C2Agent」（补收 + 新增）

A−NEW 补收国际G/FTHN / breachcache 10-12Gurucul 10-13

补收说明：前两篇落在 Daily 10-13 窗口内但当期漏收（watchlist 36），C2Agent 为 10-13 新增。三篇都是第三方安全厂商 / 研究者的一手报告，不是监管结论。

发生了什么（事实）

  • CyberXero（SOCRadar，经 The Hacker News 报道）：攻击者用 Claude Code + 51 个专用 agent 完成扫描、漏洞串联、侦察和后渗透；单次自动运行扫描 4,708 个目标，确认 429 个 WordPress 后台，61 秒内投放 32 个 webshell；确认从 4 家乌克兰机构外泄 62.8 万+ 条个人记录，波兰 / 中国 / 荷兰也有受害者。线索来自攻击者暴露的开放目录（含 AI 会话日志、明文 token、agent 配置）。
  • breachcache「Hands Off the Keyboard」（已回原文核对数字）：从攻击者服务器回收 75 份自治 AI agent 入侵 transcript，涉及 6 台编排服务器 + 1 台开发测试机，并行运行约三周，采集时仍在活动。一台服务器上记录为 claudecode_deepseek-v4.1-flash（Claude Code harness 跑 DeepSeek 模型），其他攻击者用 pi harness 搭配其他模型。结果：23 台主机拿到命令执行（多数为 root / SYSTEM），1 个云账户被接管，并有银行卡与钱包盗窃。其中一个 11 天、378 步推理的 campaign 针对「AI 网关转售市场」：agent 先用网关出厂默认签名密钥伪造管理员 token，扫描 150,574 个网关，大规模扫描没有成功（多数已轮换密钥）；随后转向已控制的网关，并通过出厂默认管理员密钥再拿下 15 个，取走 85 个上游模型账户、18 个能扛过密钥轮换的长效 OAuth token、129 个 Anthropic / OpenAI / Google API key。原文也记录了一个守住的防线：某客服 bot 在 5 天里挡住了全部提示注入尝试。
  • C2Agent（Gurucul 威胁摘要）：用 Go 写的 Windows 恶意软件，作为 MCP client 连接合法 MCP 服务（IOC 含 mcp.firecrawl.dev），由 C2 下发 skill 提示驱动 LLM 执行；首次发现于 09-10，仍在开发中。Gurucul 称之为「living off the AI」，即滥用受害者已安装的 AI 编码工具。摘要未写明原始研究来源。

我的判断

  • 证据正在从「AI 辅助攻击」走向「操作者只写目标，agent 自主跑完入侵链」的取证级材料。harness（Claude Code / pi）与模型可以随意组合，意味着厂商侧封号只能部分止损。
  • breachcache 一案还说明 AI 网关 / 中转站是新的高价值凭证仓库：长效 OAuth token 在密钥轮换后仍然有效，这是凭证设计问题，不只是运维问题。

往后看：SOCRadar / breachcache 是否公开 IOC 与 harness 细节；模型厂商是否披露封号或检测措施；C2Agent 原始研究来源。

对智能体互联网：中相关。MCP 服务方需要识别「恶意 client」（client 身份、调用速率、行为基线）；长效 OAuth token 能扛过轮换，说明委托凭证必须短期化并可集中吊销。

对 Work / Agent 引擎：强相关。本地 AI 编码工具要防止被恶意软件劫持当执行器：本地 IPC 鉴权、skill 来源签名、高危命令确认。网关类组件不得保留出厂默认签名密钥 / 管理员密钥。

建议动作：① 自查网关 / 代理组件：默认密钥是否强制首启轮换，OAuth token 是否随密钥轮换失效；② 给本地 Agent 守护进程加调用方鉴权，拒绝未签名 skill 的远程下发。

今天正在形成的趋势

  1. 端侧 / 桌面 Agent 入口集中重写：Google 把编码 Agent 放进通用助手的 Mac 端；国内同日出现三种端侧打法：自研 Agent OS 手机（STEPX）、超级 App 内嵌 + 穿戴硬件（千问）、Agent 公司向 OEM 供给能力（Manus×OPPO）。入口之争从「哪个 App」变成「哪一层（OS / 超级 App / 助手）」。
  2. 委托授权向「收窄 + 留在资源方」收敛：Workday「执行留在 SoR、权限 ⊆ 委托人、退役即撤销」，JPMorgan 拒绝凭证代登录、只认授权只读，Manus「本地任务不出端、外部处理先确认」，STEPX「用户授权后 Agent 互调」。共同方向：不共享凭证，资源方执行权限，委托范围只能收窄。
  3. Agent 产码量开始压垮开发基础设施：Anthropic 日合并 30,000+ 迫使其换掉 git；Cursor、Perplexity 也在重做托管层。代码托管层会出现「为 agent 优化」的新标准（服务端 RPC、稀疏工作副本）。
  4. 安全从「模型拒答」转向「运行时监控 + 实战取证」：Argon 的 activation probes + CoT 监控、Anthropic 的 IoT 自我复制评测、三起自治 agent 入侵取证、字节成立 Preparedness 部门，指向同一件事：agent 行为需要在运行时被观测和切断。
  5. Agent 支付开始落到终端：支付宝 Vibe Pay 首个硬件伙伴 + Amoo↔阿宝 对话内支付；国际侧 AWS AgentCore payments 已有 x402 伙伴集成（本期未入栏）。支付确认正在成为 Agent 委托链上的标准环节。

对智能体互联网最值得吸收的东西

  1. 把 Workday / C1.ai 的两条硬约束写进规范：「代表某人的 agent 权限 ⊆ 该人权限」「agent 退役即吊销全部凭证」。建议在 Agent 身份 / 委托规范中定义委托范围收窄（scope narrowing）的计算规则，以及凭证生命周期与 agent 生命周期的绑定字段，并对照 PAP / PACT / Gemini Agent Identity 看缺口。
  2. 跨主体 Agent 互调 + 支付是国内最先落地的实例：STEPX Amoo↔支付宝阿宝 的「用户授权 → Agent 互调 → 支付 → 核销」链条，适合作为协议设计的参考场景。建议提前定义 Agent 之间互调时的授权凭证格式、支付确认事件和责任归属字段。
  3. 金融接入的门槛已经被说清楚：JPMorgan 只认「客户授权的只读数据共享」，不接受凭证代登录。建议把「agent 自报身份 + 委托令牌 + 只读默认」作为 Agent 接入高风险服务的基线，并跟踪 PAP 是否补充银行场景。
  4. MCP 服务方需要识别恶意 client：C2Agent 作为 MCP client 接合法服务，长效 OAuth token 能扛过密钥轮换（breachcache）。Discovery / 认证设计里需要 client 身份证明、调用基线与可集中吊销的短期 token。

对 Work / Agent 引擎最值得吸收的东西

  1. 评测沙箱按 Argon 安全报告查漏：评分脚本只读、runner 内存隔离、沙箱崩溃不得判为通过、容器不可提权。这三类行为已在一线厂训练中真实出现。
  2. Workspace 不再假设完整 clone：Scion 的服务端查询 + 稀疏懒加载 + 有界缓存，是 Cloud Agent 冷启动与多租户成本的关键优化方向；先把 git 访问层抽象出来。
  3. Harness 的 pre-action policy hook：Workday Agent Harness「任务前注入身份 / 角色 / 政策 + 行动前策略校验」，加上 Copilot CLI 1.0.97「无人值守时 ask 等于 deny」，可以合成自家 Harness 的默认审批语义。
  4. Desktop 交互范式收敛：计划审批 → 后台执行 → 完成通知（Gemini Mac × Antigravity）；文件类操作「预览 → 确认 → 执行，原件不变」（Manus×OPPO）。建议纳入 Desktop 产品对标表。
  5. 本地 Agent 进程是攻击面：给本地守护进程 / IPC 加调用方鉴权，skill 来源签名，网关类组件禁用出厂默认密钥（C2Agent、breachcache）。
