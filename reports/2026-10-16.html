A−NEW（补收）国际G/CGHSA 2026-10-13SneakPeek 披露 10-14Daily 10-14/15 漏收

发生了什么（事实）

  • CVE-2026-88066 / GHSA-4p2j-qj3c-6x84（Published Oct 13, 2026）：Claude Desktop Windows < 1.8089.0 经 uv_spawn 启动 git.exe 未给绝对路径 → 进程先搜 CWD → 仓库内恶意 git.exe 在打开项目时即可执行（CWE-427）；CVSS 4.0 7.5 High；已修 1.8089.0（自动更新用户据称已覆盖）。解读页：theinjection.dev。
  • SneakPeek（Noma Labs，披露文，Oct 14, 2026）：Claude Code Desktop 预览窗对 >256KB 经 file:// 加载的 HTML 可执行 JS，进而读本地敏感文件外传；文称 Anthropic 2026-08-17 在 1.30096.1+ 热修；披露时 GitHub Advisory/CVE「pending」。与 88066 分列根因（预览窗 vs git 搜索路径）。

我的判断

  • 两条合看：Desktop Agent 宿主的「打开项目 / 预览产物」都是高危面——不必等 prompt injection，文件系统与预览引擎就够用。
  • 与上期 IDE 双 CVE（.mcp 尾点、VS Code 路径穿越）同气候：canonicalize + 绝对路径 + 预览沙箱成为标配作业。
  • 保留：88066 需用户确认版本；SneakPeek 的 CVE 号/正式 advisory 仍 pending，以 Noma 文 + 厂商补丁版本为准。

往后看：Cursor/其他 Desktop 是否同类 git spawn；SneakPeek 正式 CVE；野外利用。

对智能体互联网：中相关。本地 Agent 若代表用户打开不可信仓库，等于隐式扩大委托面。

对 Work / Agent 引擎：强相关。① 子进程必须绝对路径；② 预览/渲染面默认隔离；③ 打开工作区 = 安全边界事件，需审计。

建议动作：① 全员 Desktop ≥ 1.8089.0（且确认 ≥1.30096.1 预览修复）；② 红队用例：「恶意仓库 git.exe」「超大 HTML 预览」；③ 对照 CVE-2026-63093（Cursor Windows 同类叙事，若适用）。
